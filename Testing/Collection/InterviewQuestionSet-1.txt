Collection hierarchy in Java:
> The Collection is inherited from iterable which is root interface of collection framework. There are several sub interface of collection like set, list, queue etc.
> Map is not a sub interface of collection but it is part of collection framework.

Arraylist vs linkedlist:
> Arraylist is a collection which implicates the array data structure. Its index based access and faster when reading data from it. It is not synchronized and not thread safe.
> Linkedlist is collection which implicates the linked list data structure. Its best option when you do not know how much it can grow or size is not fixed. It is not synchronized and not thread safe.

How does HashMap work internally:
> Hashmap is implementation of map interface. It stores data in key value format. Internally it creates node for each key-value insertion which is a wrapper class for key and value.
>This node contains hashcode of key, key, value and next node reference. It uses hashcode to find the index in the array where it will store the node.
> Initially when hashmap created it creates an array of size 16 and when the size of array crosses load factor (0.75) it doubles the size of array and rehashes the existing nodes to new array.
> It uses linked list to store the nodes in case of collision. In case of more than treefy threshold nodes in a single index it converts the linked list to red black tree for better performance.

HashMap vs ConcurrentHashMap:
> HashMap is not synchronized and not thread safe. It can be used in single threaded environment or when you are sure that no other thread will access it.
> ConcurrentHashMap is synchronized and thread safe. It can be used in multi-threaded environment. It uses lock striping technique to achieve concurrency.
> It divides the map into segments and locks only the segment that is being accessed. This allows multiple threads to access different segments simultaneously.
> It also uses a volatile variable to ensure visibility of changes made by one thread to other threads.
> It does not allow null values and keys unlike hashmap which allows null values and keys.

fail-fast vs fail-safe iterators:
> Fail-fast iterators are designed to throw ConcurrentModificationException if the collection is modified while iterating over it. This is the default behavior of most collections like ArrayList, HashMap, etc.
> Fail-safe iterators, on the other hand, do not throw ConcurrentModificationException. They work on a copy of the collection and allow modifications to the original collection while iterating. Examples include CopyOnWriteArrayList and ConcurrentHashMap.
> Fail-safe iterators are generally slower than fail-fast iterators because they create a copy of the collection.

ListIterator vs iterator:
> ListIterator is a sub-interface of Iterator and is specifically designed for List collections. It allows bidirectional traversal of the list, meaning you can iterate both forwards and backwards.
> ListIterator allows concurrent modification of the list while iterating unlike iterator which does not allow concurrent modification.
> ListIterator also provides methods to add, remove, and replace elements in the list while iterating, which is not possible with a regular Iterator.

When to use HashMap over TreeMap:

> HashMap is generally preferred over TreeMap when:
1. You do not need sorted order: HashMap does not maintain any order of its elements, while TreeMap sorts its elements based on their natural ordering or a custom comparator.
2. Performance: HashMap has O(1) average time complexity for insertion, deletion, and access operations, while TreeMap has O(log n) time complexity due to its underlying red-black tree structure.
